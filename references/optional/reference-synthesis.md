# Reference synthesis

Use when the user supplies benchmarks, names a reference family, asks for a
revision against an existing master, or when the task needs stronger aesthetic
evidence. Reference images are benchmark-only unless they receive a separate
approved content role. Record source and rights status; never bundle unknown-
rights screenshots into the Skill or final artifact.

## Human-made reference decomposition

For two to four genuinely adjacent examples, record:

| Question | Observation |
| --- | --- |
| First attention and reading path | |
| Type hierarchy and scale ratios | |
| Operations inside the image | |
| Content and composition added outside the image | |
| Role of lines, icons, blocks, shapes, and material | |
| Balance of local density and quiet space | |
| Transferable principle | |
| Signature surface move to refuse copying | |

Identify the reference family by problem — film poster, cultural poster,
editorial sequence, evidence deck, data product, immersive interface — rather
than by an aesthetic adjective. Select techniques only after the subject and
audience task are understood.

## Synthesis rule

Translate references into relationships: scale contrast, type-image contact,
crop, repetition, evidence hierarchy, material continuity, or interaction
rhythm. Do not average references into a mood board and do not copy their grid,
font, palette, logo, icon drawing, or signature motif.

Other carriers may inherit scale courage, typographic imagery, image treatment,
and relational density from poster evidence. They may not inherit a movie-
poster surface when the reading task is a deck, article, or product flow.

## Revision contract

After feedback, record and obey:

- preserve;
- remove;
- strengthen;
- locked foundations;
- user-named reference level.

Revise these deltas directly. New explicit feedback outranks earlier defaults.
Never reintroduce a rejected device under a new name.
