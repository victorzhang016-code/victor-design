# Task brief and autonomous fallback

Use this before substantial new work: a new campaign, poster, social set,
product surface, deck, named product/brand, ambiguous brief, or unattended
race lane. It makes the task knowable without importing any palette, layout,
or visual style.

A task that meets the light-lane conditions in `../../SKILL.md` does not
create this file; it records the same answers inline in the dialogue. If any
light-lane condition breaks mid-task, create this record before continuing.

## Minimum record

Create `TASK_BRIEF.md` beside the task control file. Keep it concise and use
only facts available to every permitted entrant.

```markdown
# Task brief

## Authority and scope
- Controller / user instruction:
- Deliverable surface, count, canvas, editable-source requirement:
- Interaction policy: user approval | controlled unattended run

## Reader and truth
- Reader action and viewing condition:
- Required facts, copy, and refusals:
- Allowed sources and material boundary:
- Unknowns that must remain visible:

## Asset decision
- Content-essential assets (why removal loses information):
- Identity assets (named products/brands, if material):
- Supporting-atmosphere assets (approved role only):
- Source / rights / generation route:

## Form questions
- Role of each page, state, or canvas:
- Viewer distance, dwell time, and access context:
- Capacity check with real copy:
- Current-task visual mother object, relation, or event:
- Title-removal test: what remains specific to this subject?
- Single-canvas counterfactual, when relevant:

## Autonomous fallback
- Least-assumptive permitted choice:
- Counterfactual result and unresolved risk:
```

## Decision rules

1. Treat a controller and the user's latest explicit instruction as the source
   of scope. Verify external facts only when they are material to the output;
   cite the source or mark the fact unknown.
2. Run the asset-necessity test for every visual asset: remove it mentally. If
   reader understanding, evidence, identity, or an approved atmosphere role is
   unchanged, omit it. Do not use a real-looking image, logo, screenshot, or
   interface to imply an unsupported fact.
3. Answer the form questions before selecting a palette, typeface, texture, or
   layout. They determine the carrier; `style-evidence.md` then helps express
   the answer in the owner's voice.
4. In an unattended run, replace a conversation-only checkpoint with this
   record and a visible risk note. Continue only on the least-assumptive path
   allowed by the control layer. Never create fake approval, fake assets, or
   fake certainty.

## Boundaries

Do not require three visual directions, a style library, brand marks irrelevant
to the reader's task, or a generated image merely because another design skill
uses them. This brief protects judgment; it does not prescribe an aesthetic.
