# Victor Design routing

## Default chain

1. `workflow/task-brief.md` — establish the current task's authority, facts,
   reader, material boundary, asset necessity, and form questions. Use before
   substantial, ambiguous, branded, or unattended design work.
2. `aesthetic-core.md` — establish cause, task, tension, and proposition.
3. `style-evidence.md` — select task-relevant evidence from the owner's
   authored work; never import a preset by default.
4. `workflow/density-and-care.md` — the positive craft model: page layers,
   density calibration against the reference, and the per-page care pass.
5. `copy-discipline.md` — voice rules and the AI-flavor blacklist for all
   deliverable copy.
6. One adapter — `adapters/poster.md`, `adapters/product-ui.md`, or
   `adapters/slides.md`.
7. `operations/execution.md` and `operations/three-gates.md` — obtain approval,
   record asset provenance, and release work in order.

## Conditional tools

| Need | Load | Boundary |
| --- | --- | --- |
| Asset sourcing, cutout, generation, SVG, perspective, or editable Figma | `operations/production-toolkit.md` | Use only after Gate 1 releases the named role. |
| Concrete Figma/PPTX/interactive-HTML build pipelines | `operations/delivery-implementations.md` | Load at Gate 3, after the master is approved. |
| Editable poster translation or correction of font/material/perspective drift | `operations/figma-fidelity.md` | Treat the approved render as the golden source; translation is not redesign. |
| Any master review or completion claim | `operations/review.md` | Review is a visual veto; scripts are supporting evidence only. |
| Revision-led work or a user-adjusted reference | `optional/reference-synthesis.md` | Preserve declared character while correcting declared flaws. |
| Social, landing, presentation, or multi-format communication | `optional/communication-surfaces.md` | Adapt the core; do not import a platform template. |
| Long-running project governance | `workflow/project-governance.md` | Project records cannot replace Gate approval. |

## Precedence

1. User-confirmed subject, acceptance criteria, and explicit adjustments.
2. Truth, safety, accessibility, and the primary task.
3. Approved project/surface decision.
4. `SKILL.md`, aesthetic core, and style evidence.
5. Relevant adapter and operations.
6. Optional references and external defaults.
